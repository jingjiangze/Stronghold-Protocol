# 静态资源加速与镜像（含国内 CDN）

这份文档只做一件事：**让玩家长按 F12 看到的静态请求不再落在开服机器上**。
它同时是 `auto-windows` / `auto-docker` 两个套件共用的唯一指导文件。

## 0. 先分清两类文件，处理方式完全不同

| 类别 | 例子 | 能不能放进公开镜像 |
|---|---|---|
| **你自己的构建物** | APK、`content-slim-shell-*.zip`、服务端压缩包、你写的 JS/CSS | ✅ 可以，随便镜像多站点分发 |
| **游戏本体素材** | `public/assets/**`、`public/fonts/**`、`data/local-assets.json`（约 313 MB，属第三方版权） | ❌ 不做公开镜像目录；只在**你自己的服务器/私有桶**里，为你这台服的访客服务 |

规则很实际：玩家从你这台服下载素材，本来就是这台服的功能；**把它换成一个更快的地址下载同一批文件**是加速；把它做成任何人可枚举、可转发的公开仓库，就变成分发。下面所有方案都只做到前者。

## 1. 三级加速，按投入排序

### L1 边缘缓存（0 成本，先做这个）
让 Cloudflare 缓存你这台服的静态响应。要点：
- **Cloudflare 默认只按扩展名缓存，`.mp3/.ogg` 不在名单里** → 音频必须显式规则才会命中边缘。
- 两种做法：
  1. **Zone → Caching → Cache Rules → 新建规则**（推荐、无需代码）：
     匹配 `starts_with(request.uri.path, "/assets/") or starts_with(request.uri.path, "/media/") or starts_with(request.uri.path, "/vendor/") or starts_with(request.uri.path, "/fonts/")`
     → Eligible for cache → **Custom TTL 30 天** → 保留浏览器 `Cache-Control`。
     若你的令牌没有 `Zone Cache Rules: Edit` 权限，这一步只能在面板点。
  2. **Worker 里 `cache.put()`**（无需 Cache Rule 权限）：见 L2。
- 校验：带 `?cb=<随机>` 绕开缓存看 `cf-cache-status: MISS→HIT`；不带绕开的第二次请求应变 HIT。
  同一路径反复测同一条不说明问题（CF 会按缓存键复用），务必换 query。

### L2 私有桶 + 穿透回源（推荐架构，盒子零云凭据）
```
玩家 → 你的域名/assets/**（或 /media/**）
        → Worker：先读边缘缓存 → 再读私有 R2 → 命中直接回（带 ACAO、30 天）
                    → 都没有：向你这台服取那一个文件 → 存边缘缓存 → 回给玩家
```
好处：**每个文件穿过你家宽上行的次数 ≤ 1**；上游改了素材，下一版自动跟上；不需要上传脚本、不需要在服务器放任何密钥；桶不设公开域、不列目录，因此不是公开镜像。

现成两件，选一种形态：

| 文件 | 形态 | 需要动的地方 |
|---|---|---|
| `cdn/same-origin-assets.worker.mjs` | **同源路由**（线上在用，推荐）：Zone Route 把静态前缀交给 Worker，其余路径原样回你的服务器 | 只加路由，客户端与 nginx 都不用改；素材 URL 不变 → 无跨源/画布污染风险 |
| `cdn/asset-cdn.worker.mjs` | **跳转镜像**：nginx 对静态前缀 302 到镜像域名 | 要改 nginx 的 `$mirror`，且跨源要过 CORS |

同源形态要建 4 条路由（每个游戏域名各一条前缀），面板里 `Workers & Pages → 你的 Worker → Settings → Routes`，或 API：
```
POST /zones/<zone>/workers/routes   body {"pattern":"<你的域名>/assets/*","script":"<worker 名>"}
```
四个前缀都要：`/assets/*`、`/media/*`、`/vendor/*`、`/fonts/*`。**只挂 `/assets/` 是常见漏法**：`/media/`（音频，扩展名都没有）、`/vendor/`、`/fonts/` 就还全压在你家上行上。

实测（同一台国内盒子出网，同一个 2.0 MB 的 mp3 / 660 KB 的 js）：

| 路径 | 吞吐 | 首字节 |
|---|---|---|
| 服务器直接出（未挂 Worker） | 0.04–0.15 MB/s | 1.2–2.4 s |
| Worker + 私有桶命中 | **1.5 MB/s** | 0.23–0.4 s |
| Worker + 边缘缓存命中 | 1.3–2.5 MB/s | 0.2–0.7 s |
| 桶的自定义域名直链 | **8.9 MB/s** | 0.18 s |

两条注意事项，都是踩过才知道的：
1. **Worker 的响应默认不吃 Zone 缓存**，所以必须代码里 `cache.put()`（本文件 L1 的说法在 Worker 形态下不成立，别去申请 Cache Rule 权限）。
2. **桶共享时绝不回写桶**。穿透取到的文件只写边缘缓存；写回共享桶等于让一台服的构建覆盖另一台服的同名对象。

### L2.5 GitHub 制品镜像（只放你自己的构建物）
`cdn/github-mirror.worker.mjs` 复用下载站（`jingjiangze/stronghold-download`，开源）的那套判断，把 Pages + CI 两条链压成单个 Worker：

- `GET /api/latest` —— 由 Cloudflare 出口代取 GitHub release 列表，边缘缓存 5 分钟，同时把最后一次成功结果写进桶里当快照；上游挂了就用快照并标 `_stale`。
  **为什么要代理**：访客浏览器匿名打 `api.github.com` 会按 IP 撞 403（国内出口稳定复现），页面于是把旧快照当最新版显示。
- `GET /d/<tag>/<file>` —— 选路跳转：桶里有这份构建**且字节数在容差内** → 302 到你的域名；否则 302 到公共前缀加速器；响应带 `x-download-source` / `x-download-reason` 供复核。
- `GET /mirror/<tag>/<file>`（或 `/d/...?pull=1`）—— 真正抓一次 GitHub 资产，**按 GitHub 给的 sha256 逐字节校验后**才落桶。键名不可信：这条链上出现过 `apk/stronghold-v2.8.0.apk` 是 521,193,612 B 而 release 资产是 543,630,883 B 的事，所以判据只能是字节/摘要，不能是名字。
- `REPO` 是写死的常量，路径要过白名单，`..` 直接 403 —— **不做开放代理**，否则它就变成任何人转发任何人地址的公共服务。

红线照旧：这里只放**你自己发布的文件**（APK、服务端压缩包、内容包、补丁）。游戏本体素材不进公开镜像，它们只走 L2 的私有桶。
另外：**给用户看的直链不要带 `?cb=`**——带 query 的请求会让 R2 域名无视 `Range` 直接回整包，等于废掉断点续传、让多线程下载器每路重下整包；cache-buster 只用在探测（HEAD）里。


### L3 国内 CDN 加速（要花钱和备案）
适用：玩家集中在国内、且你能接受一次配置。
- **前提（硬条件）**：国内节点加速要求**已备案域名** + 你自己的证书；没有备案就只能用海外节点（回到 L1/L2）。
- 常见组合：对象存储（腾讯 COS / 阿里 OSS / 七牛 / 又拍云）+ 对应 CDN 域，回源地址填你这台服的 `/assets/`；上传侧用 `aws s3 sync`/`rclone` 对**清单差分**同步（`assets-manifest.mjs` 生成 `path,size,sha256`，只传变化的）。
- **必须配的两件事**：① 允许来源（CORS）只放开你自己的游戏域名；② 防盗链（Referer/UA 或签名 URL），避免变成公开仓库。
- 成本提醒：素材 313 MB × 访客数是真金白银；先做 L1/L2 通常就够，L3 留给"人多到 CDN 回源都吃紧"的阶段。

## 2. 让游戏服不再下发静态（两行配置，随时可回退）

Windows（套件已带）：nginx 对静态前缀 **302 到镜像域名**，客户端自动跟随；镜像不可用时按 `try_files`/回源兜底，不会白屏。
Docker：`tools/auto-docker/nginx/default.conf` 里那个 `location ~* ^/(assets|vendor|fonts|media|data)/ { set $mirror ""; ... }`，
把 `$mirror` 设成你的镜像基址即可（留空=行为不变，仍由服务器出）。

**注意别越界**：`/data/*.json` 与 `/` 不要交给镜像（它们是这台服的运行时状态与入口，缓存会导致版本错配）。

## 3. 换版时的素材同步（这是"自动"的部分）
1. 上游发新版 → 更新器换代码（蓝绿，不打断在线玩家）；
2. 若清单变了：按上游流程取素材（`npm run assets` / `tools/fetch-assets.mjs`，或你自己的提取流程）→ 重新生成 manifest；
3. 镜像层：L2 靠穿透自动跟上（**推荐**，无需任何动作）；L3 跑一次差分 `rclone sync --size-only`/按 manifest 比对上传；
4. 把镜像 URL 的 `?v=<APP_VERSION>` 换掉 → 玩家下一次进场即取新版；老版本文件保留一段时间，正在玩的人不会 404。

## 4. 验收清单（做完照这个打勾）
- [ ] `stronghold.<你的域>/healthz` 正常，且 `app` 是新版
- [ ] `/assets/...`、`/media/...`、`/vendor/...`、`/fonts/...` 四条都带 `X-Served-By`（说明真的挂上 Worker 了，不是还在吃你家上行）
- [ ] 同一 URL 第二次请求 `X-Asset-Source: edge` 且 `CF-Cache-Status: HIT`（第一次应是 `r2` 或 `origin`）
- [ ] 桶里没有的文件（例如新加的 `/vendor/`）仍然 200 而不是 404——这条验的是穿透兜底，最容易漏
- [ ] `..` 构造的路径回 4xx，不返回任何桶外内容
- [ ] `/assets/...`、`/media/...` 的 `content-type` 与换源前一致（音频错 MIME 会播不出）
- [ ] WebGL 素材仍能加载（说明 CORS 通过）；`crossOrigin` 的图尤其要看控制台
- [ ] Range 请求返回 206 + `Content-Range`（音频拖进度条）
- [ ] Worker 关掉/删掉路由后游戏仍可玩（说明回源形态没问题）
- [ ] 桶/CDN 上不存在公开列目录，且公开页面里没有指向素材桶的直链


> 一键包位置：`tools/auto-windows/`（Windows）与 `tools/auto-docker/`（Docker）。
