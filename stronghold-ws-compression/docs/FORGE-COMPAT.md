# 与 Forge 工坊包 / mod 管理器的边界

对象：`https://github.com/XiaMo233M/Stronghold-Protocol-Forge` 的工坊体系
（文档 `docs/WORKSHOP.md`），以及它的分发站 **SP MODSITE** `http://47.103.14.217:25570/`。

---

## 1. 先说结论：**工坊包开不了传输层压缩**

这是审计里最关键的一条，它决定了「兼容」是什么意思。

工坊包在服务端能声明的只有两组（`pack.json`）：

| 字段 | 形状 | 能力 |
|---|---|---|
| `server` | `{ preDispatch: { module, policy, intercepts } }` | 拦下**入站的 C2S 消息**再决定怎么处理 |
| `routes` | `[{ path, file, cache? }]` | 服务包内的**只读 `.json`** |

而传输层压缩是 `WebSocketServer({ perMessageDeflate })` 的**启动选项** ——
它作用在**建连时刻的扩展协商**上，不在消息分发路径上，也不在 HTTP 路由面上。
`preDispatch` 拿到消息时，握手早就完成了，deflate 开没开已经定死。

**所以没有任何一种 `pack.json` 写法能让工坊包打开压缩。** 一个声称能做到的包只能是
「声明了却用不了」，而 Forge 的纪律正是**拒绝整个包**（`docs/WORKSHOP.md` §1.9.3 末尾）。

⇒ 「兼容 mod 管理器」只能落在这两件事上：**读写同一套约定**，以及**可共存**。

## 2. 只读接口：逐条对齐 Forge 的 `routes`

`src/readonlyRoutes.mjs` 的约定**逐条抄自** `docs/WORKSHOP.md` §1.9.2，不是「差不多」：

| Forge 的规则 | 本包 | 为什么照抄 |
|---|---|---|
| 只 `GET` / `HEAD`，其余 `405 Allow: GET, HEAD` | ✅ | 动词面越窄，越没有要审计的东西 |
| **精确匹配**，无重写、无前缀、无目录列表 | ✅ | 目录穿越不是「被检查出来」的边界，而是**没有可穿越的目标** |
| 只服务 JSON，`.js` / `.html` 一律拒 | ✅ | 那是代码执行面，不是数据面 |
| `cache`: `no-cache`(缺省) / `no-store` / `public`(→`max-age=86400`) | ✅ | 同一个三选枚举，运维不用记两套 |
| 声明路径**先于**核心静态挂载被查找 | ✅ | 一条声明过的路径不会因为磁盘上恰好有同名文件而变成别的东西 |
| 声明了但不存在 = **404**，不回落 | ✅ | 同上 |

**唯一的差别**：Forge 的 `routes` 服务包内**静态 `.json` 文件**；这里的两条是**算出来的**
（实时状态与计数器）。所以本包不注册进 `pack.json`，而是挂在宿主 HTTP 链的最前面 ——
语义一致（只读 JSON、精确路径、同样的 cache 枚举），来源不同。

## 3. 分发：包可以进 mod 管理器，模块不能

SP MODSITE 收的是**工坊包 zip**（`POST /api/submit?name=&note=&homepage=`，
`content-type: application/zip`；列表 `GET /api/mods`；下载 `GET /api/file/{id}`）。

于是这一层可以、也应该作为**一个工坊包**分发出去 —— 但它的内容是**只读数据**：

| 进包的东西 | 形态 | 为什么它可以 |
|---|---|---|
| 本模块的构建产物 / 文档 | 包内静态文件 | 是数据 |
| 只读状态快照（某个 build 的实测数字） | 包内 `.json` | 正是 `routes` 通道设计的东西 |
| **压缩开关本身** | ⛔ | 启动选项，包改不了（§1） |
| **`wsCompression.mjs` 当代码注入** | ⛔ | `.js` 在服务面就被拒 |

⇒ **分布式安装做不到；能做的是「分发 + 人工安装」**：mod 管理器负责让社区拿到并验证，
装上去仍然是运维改一个环境变量重启。**别把这个边界说成「装上就生效」**，那是这类包最容易
制造的一类静默失败。

## 4. 可共存性（已核）

- 本包**不改** `pack.json` 的任何字段，不注册进工坊的身份哈希（DESIGN §28.2）
- 只读路由用的是**独立的路径空间**（`/ws-compression/*`），不与包内 `routes` 的声明路径冲突；
  宿主若按 Forge 的规则「声明路径优先」，本包挂在更前面一层，同样只回答**精确等于**的两条
- 压缩是**传输层**，工坊包是**内容层**：包叠加的是 `data/*.json`，压缩改的是同一批字节怎么上线路，
  两者正交

---

## 5. 给 AI 的行动准则

1. **不要说「工坊包可以开压缩」**。`preDispatch` 拦的是消息，压缩开在握手。
2. **不要再发明一套只读路由约定**。要么用 Forge 那套（本文 §2），要么说明为什么不一样。
3. **区分「分发」与「安装」**。mod 管理器解决前者，后者是运维。
4. Forge 的 `api` 字段是 `MOD_API_VERSION` 兼容门（声明了才比对，不含则整包拒
   `MOD_API_INCOMPATIBLE`）—— 一个包若声明了 `server`/`client`，要跟着这个版本走。
